## 项目介绍
一个基于自研 Multi-Agent 编排框架的 **小哈工单智能诊断助手**——基于 RAG 的商户投诉快速定位系统。针对商户投诉工单实现**自动化的问题定位、日志追踪、根因分析和归属方判定**，采用**codeAgent、OperationAgent和DataAgent将前端+后端+数据三条排查路径设计**，联合排查半小时的流程压缩到 12 秒。



## 简历-开发类-AI开发: 侧重链路搭建/框架应用/工程指标优化
**项目背景:**

负责搭建企业商户工单智能诊断智能助手工程链路，基于AgentScope实现多Agent 协同、Skill插件化加载、RAG知识库、WebSearch、记忆系统、重试熔断与评测脚本，<font style="color:rgb(15, 17, 21);">系统支持商户服务人员通过自然语言完成工单根因分析、解决方案推荐、历史工单检索与相似案例匹配，以及故障修复建议等诊断全流程操作。</font>

+ **搭建 Agent 主链路 ：**基于 AgentScope 的 AgentBase/Msg/OpenAIChatModel 实现统一通信协议，完成 CLI → IntentionAgent → OrchestrationAgent → Skill Agents → MemoryManager 的端到端调用链路。支撑工单智能诊断助手从用户输入到最终回答的完整工程闭环。采用了 Intention-Orchestration 分层、LazyAgentRegistry、记忆系统与弹性机制等作为骨架，但对主入口、专业诊断 Agent、领域记忆模型和 Skill 组织方式做了诊断域适配。
+ **实现 Multi-Agent 编排与 Loop 决策双层调度 ：**设计 OrchestrationAgent 负责轮内并行调度（同 priority asyncio.gather 并行，不同 priority 按依赖顺序），LoopDecider 负责轮间迭代决策（done / cross_verify / need_info 三态转移），支撑 3 轮闭环（收集→诊断→验证→判定）。归属准确率 93%，闭环成功率 87%，平均耗时约 30s→15s。
+ **<font style="color:rgba(0, 0, 0, 0.9);">原子化 Skill 架构设计与</font>****Skill插件化架构: **<font style="color:rgba(0, 0, 0, 0.9);">按商户管理、经营、结算三大业务域抽象出 30 个原子 Skill，每个 Skill 对应单一数据源，遵循"原子化 + 可组合 + 可观测"设计原则，核心验证了订单支付异常、资产分配失败、结算金额不符 3 个高频场景。调度上不是完全自由式组合，而是由 CodeAgent / OperationAgent / DataAgent / ResolutionAgent 在职责边界内受控调用；并</font>设计了 .claude/skills/<skill>/SKILL.md + script/agent.py 目录规范，通过LazyAgentRegistry自动扫描、动态import、按需实例化和缓存，降低系统启动加载压力，并支持通过新增Skill目录快速扩展新业务能力<font style="color:rgba(0, 0, 0, 0.9);">。</font>
+ **构建RAG知识库模块:**<font style="color:rgb(15, 17, 21);">使用Milvus Lite + SentenceTransformer/BGE实现故障诊断文档、商户操作手册、商户退款政策、支付结算规则、历史工单处理记录、接口错误码映射表等文档的向量化存储与召回，结合metadata解析（合同套餐、订单状态、车服商户等级、支付通道、城市区域）和检索增强的答案生成，使工单故障诊断与商户自助排障问答准确率达到95%左右。接入WebSearch与业务系统查询工具（订单状态查询、退款日志追踪、商户配置核对），加速"用户投诉→业务上报→研发排查"全链路响应。</font>支持低质URL过滤、搜索失败降级和工具结果结构化返回，补齐企业知识库无法覆盖的实时信息查询能力。
+ **构建双层记忆与上下文注入系统** ：实现 ShortTermMemory（会话级，10 轮 FIFO）+ LongTermMemory（跨会话 JSON 持久化 + LLM 摘要注入），支持偏好追加/覆盖语义。诊断时三路径上下文并行注入，避免跨角色信息割裂。
+ **增强工程稳定性 ：**增加 LLM 调用指数退避重试、CircuitBreaker 熔断、健康检查、6 策略鲁棒 JSON 解析兜底、单 Agent 失败隔离，确保外部模型或工具异常不中断主链路。
+ **开发评测工具链 ：**基于内部工单系统历史数据均衡采样 1000 条工单，覆盖正常闭环、多意图、信息缺失、边界异常、跨角色冲突等长尾场景。开发 runner 脚本支持批量执行、计算意图准确率/实体召回率/RAG 命中率/闭环成功率/归属准确率/MRR 等指标并生成报告，为 Prompt 迭代、调度策略调整和诊断逻辑优化提供可复现的工程化验证能力。
+ **可视化：**开发 React + SSE 前端诊断面板，实时展示 Agent 思考链与归属判定矩阵。<font style="background-color:#FBF5CB;">（选做）</font>

## 简历-算法类-侧重正向效果优化的手段/指标/优化成果
技术栈Python + AgentScope + FastAPI + Docker

**项目背景:**

针对传统LLM单轮差旅问答中意图识别不稳、上下文遗忘、企业政策回答不准、工具调用不可控等问题构建基于LLM+RAG+Memory+Multi-Agent Orchestration的差旅智能助手，并围绕意图识别、检索增强、记忆利用和调度策略进行效果优化。  
**核心工作:**

+ **优化多意图识别链路:**设计 IntentionAgent，通过结构化 Prompt 引导模型输出 reasoning/intents/ key_entities / rewritten_query/ agent_schedule,支持多意图识别、置信度判断、实体抽取和Query 改写，使意图识别准确率由约65%提升至90%+。
+ **构建上下文增强机制:**融合短期对话窗口、长期历史摘要、用户偏好和历史行程信息，解决多轮对话中的省略、指代和历史依赖问题，使模糊需求和follow-up场景下的实体抽取准确率提升至90%左右。
+ **优化RAG问答效果:**基于 Milvus Lite+BGE/SentenceTransformer 构建企业差旅知识库，设计文档切分、metadata标注、top_k召回、余弦相似度检索与基于证据的答案生成策略，使政策问答准确率达到95%左右，并降低制度类问题幻觉。
+ **引入Query改写与检索路由:**根据用户问题区分企业知识库查询、实时网络查询、天气查询和历史记忆查询，避免所有问题统一走通用LLM，提升答案可靠性和工具调用命中率。
+ **设计偏好记忆抽取策略:**通过PreferenceAgent识别用户长期偏好，支持偏好追加与覆盖，减少重复询问，使用户偏好记忆准确率达到95%左右。
+ **优化多Agent调度策略:**将信息收集类Agent设置为Priority1并行执行，将行程规划Agent设置为Priority2依赖执行，减少不必要串行等待，使平均响应时间由约30秒下降至15秒左右。
+ **建设算法评测集合:**基于线上query均衡采用出1000个覆盖真实、多意图、模糊需求、边界负样本的评测集合，覆盖多意图组合、真实分布、模糊follow-up、知识边界、偏好冲突、工具失败等样本，沉淀离线评测指标和Rubrics，支持模型、Prompt、RAG和调度策略持续迭代。
