# 工单诊断知识库

## 一、订单支付异常

### 1.1 订单状态不一致
- 常见原因: 退款回调脚本偶发死锁，订单状态未同步更新
- 排查方法: 对比订单表(order_main)、支付表(payment_records)、结算表(settlement_records)三表状态
- 典型症状: 支付表显示已退款(refunded)，订单表仍显示待退款(pending_refund)
- 解决方案: 手动修复订单状态 → 排查脚本死锁问题 → 增加重试机制+告警
- 历史案例: WO-20260515-0312, WO-20260622-0401, WO-20260730-0508

### 1.2 支付成功但服务未生效
- 常见原因: 支付回调超时(timeout 505)，后端未收到支付成功通知
- 排查方法: TraceRequestLog 查支付回调日志 → GetAssetAllocation 确认用户侧权益是否激活
- 解决方案: 手动触发权益激活 → 排查回调链路 → 转后端团队处理
- 代码排查结论: 接口正常返回200，非代码Bug
- 数据排查结论: 支付表已支付，订单表待激活，权益表未分配

### 1.3 退款未到账
- 常见原因: 支付通道延迟、退款审批未通过、打款链路失败
- 排查方法: GetOrderRefund 查退款状态 → GetSettlementStatus 查结算单 → GetPaymentChannel 查支付通道
- 解决方案: 确认退款审批流程 → 联系支付通道排查 → 手动补退

### 1.4 订单状态显示已完成但用户未收到权益
- 常见原因: 前端状态与后端数据库状态不同步，或缓存未刷新
- 排查方法: GetOrderDetail 查后端状态 → GetOrderTimeline 查时间线 → GetAssetAllocation 核验权益
- 解决方案: 刷新前端缓存 → 同步后端状态 → 如权益未分配则手动激活

## 二、资产分配异常

### 2.1 资产分配余额不足
- 常见原因一: 实际剩余额度不足
  - 排查: GetAssetPool 查总额度/已分配/剩余可用
  - 解决: 回收未使用额度 / 采购新套餐
- 常见原因二: 目标用户在保护期内
  - 排查: GetUserBinding + GetProtectionPeriod 查用户归属
  - 解决: 等待保护期结束 / 联系业务解绑
- 常见原因三: 操作者无跨商户权限
  - 排查: GetMerchantPermission 查角色权限
  - 解决: 申请跨商户分配权限

### 2.2 库存莫名减少
- 常见原因: 系统自动回收（过期、违规）、脚本批量操作
- 排查方法: GetAssetRecycle 查回收记录 + 操作日志审计
- 解决方案: 确认回收原因 → 如误操作则恢复额度 → 增加操作通知

### 2.3 用户绑定归属冲突
- 常见原因: 保护期未结束、用户已绑定其他商户
- 排查方法: GetUserBinding 查绑定关系 → GetProtectionPeriod 查保护期状态
- 解决方案: 确认保护期到期时间 → 联系业务解绑 → 重新分配

## 三、结算金额异常

### 3.1 结算金额与合同不符
- 常见原因一: 结算标签被脚本误刷（如联营变直营，分润比例错误）
  - 排查: GetMerchantContract vs GetSettlementRule 对比分润比例
  - 解决: 联系数据侧修复结算标签 → 人工补差 → 增加标签变更审批
- 常见原因二: 对账周期不匹配
  - 排查: GetReconciliation 查对账差异明细
  - 解决: 调整对账周期 → 补录遗漏账单

### 3.2 结算迟迟未到账
- 常见原因: 打款链路失败、支付通道故障、结算单未捏结
- 排查方法: GetSettlementStatus → GetSettlementTimeline → GetPaymentChannel
- 解决方案: 确认结算单状态 → 排查打款链路 → 联系支付通道
- 典型时间线: 账单生成 → 捏结 → 推送 → 打款 → 完成，任一步骤卡住都会导致未到账

### 3.3 账单出现不明费用
- 常见原因: 业务单误推送、计费规则变更未通知、费用类型配置错误
- 排查方法: GetBillDetail 查明细 → GetBillCalculation 查计算过程 → GetBillingConfig 查计费规则
- 解决方案: 逐笔核对业务单 → 纠正计费规则 → 重新生成账单

## 四、商户管理异常

### 4.1 商户入驻审核积压
- 常见原因: 审核流程积压、资质材料不完整、系统自动驳回
- 排查方法: GetMerchantOnboarding 查入驻状态 + GetMerchantContract 查合同状态
- 解决方案: 审核队列催办 / 补充资质材料 / 手动通过

### 4.2 员工权限异常
- 常见原因: 角色未分配、权限过期、组织架构变更未同步
- 排查方法: GetMerchantPermission 查权限配置 + GetMerchantOrgTree 查组织架构
- 解决方案: 重新分配角色 → 同步组织架构 → 刷新权限缓存

### 4.3 商户被冻结
- 常见原因: 风控触发（异常交易、违规操作）、合同到期未续签
- 排查方法: GetMerchantBlacklist 查风控记录 + GetMerchantCoopStatus 查合作状态
- 解决方案: 联系风控团队核实 → 提供解限材料 → 续签合同

### 4.4 商户标签错误
- 常见原因: 数据脚本误刷、入驻时录入错误、标签变更未审批
- 排查方法: GetMerchantProfile vs GetMerchantContract 对比类型标签
- 解决方案: 修正商户标签 → 追溯标签变更记录 → 增加变更审批流程

## 五、通用排查方法论

### 5.1 三路径排查框架
工单诊断应同时从三条路径推进：
1. 代码路径（🔴）: 查API日志、接口返回、配置开关 — 排除代码Bug
2. 操作路径（🟡）: 查用户操作日志、业务流程合规性 — 排除操作失误
3. 数据路径（🟢）: 跨表对比数据一致性 — 发现脏数据/同步问题

### 5.2 交叉验证原则
当单一路径结论为"正常"时，不可直接判定。必须三条路径都跑完，在交叉验证中发现矛盾点。例如：代码路径返回200正常，操作路径流程合规，但数据路径发现订单表≠支付表 → 根因在数据侧。

### 5.3 归属方判定标准
- 前端代码: 渲染错误、缓存问题、状态展示不同步 → 归属前端
- 后端接口: API返回异常、超时、逻辑错误 → 归属后端
- 数据脚本: 数据不一致、标签错误、同步失败 → 归属数据侧
- 用户操作: 不符合标准流程、信息填写错误 → 归属用户
- 业务配置: 规则配置错误、权限未分配、功能开关关闭 → 归属业务配置
