# 开发踩坑记录（面试版本）

> 场景：一个多 Agent 的工单智能诊断系统（Intention → Orchestration → Code/Operation/Data/Resolution），上线前离线评测端到端 Pass@1 只有 77.27%，10 个失败。

**一句话复盘**：一开始我下意识以为是 RAG 或记忆系统的问题，但我给评测脚本加了「分环节命中率统计」（Intent / Entity / RAG / Tool / Agent / Verification 六段），用数据定位到真正的瓶颈是 **Entity Resolution（实体解析）**——多数失败不是缺 ticket_id，而是「商户名 → merchant_id」这层解析缺失（原正则 `\b\d{4,6}\b` 在 Python Unicode 模式下把中文当单词字符，导致「商户2037」里的数字匹配不到），以及「只有商户号时无法反查订单号」；于是我按「数据闭环」做了三阶段优化：① Entity Resolution（商户名→ID、商户→订单反查）、② Tool 能力（新增 `resolve_merchant` / `resolve_order`）、③ 评测升级（根因评测从脆弱的 Keyword Match 改为 Structured 多字段 + Semantic 软匹配），每一步都重新跑评测量化验证，Pass@1 依次走到 81.82% → 86.36% → 90.91% → 100%。这件事最大的收获是：**「用数据定位瓶颈、用评测闭环验证」远比「凭直觉预判优化」高效**——之前做的 RAG 增强和缓存其实都没打在这个真正的瓶颈上。
