# 开发踩坑记录（面试版本）


> 场景：架构变动，从 Agent Orchestration 到 Deterministic Workflow 的架构收敛。

这个项目一开始是团队按照生产级 Multi-Agent Orchestration 的思路设计的，第一阶段主要目标是快速验证工单诊断的完整闭环，第一阶段的目标其实是先把工单诊断的完整链路跑通，所以当时采用的是比较典型的 Multi-Agent Orchestration 架构。上层负责意图理解和任务规划，中间由 OrchestrationAgent 做 Agent 调度，下层按照前端、运营、数据等排查路径拆成 CodeAgent、OperationAgent、DataAgent，再通过 Skill 和 Tool 获取业务数据，最后做交叉验证。

系统跑通以后，补了离线评测。初始 Pass@1 是 77.27%，我们把链路拆成 Intent、Entity、RAG、Tool、Agent、Verification 六个环节，根据失败样本逐步优化，最后 Pass@1 提升到 100%。

在这个数据闭环建立以后，我再回头 review 编排代码时发现一个比较有意思的问题：OrchestrationAgent 虽然继承了 AgentBase，但实际上没有 LLM 调用，主要做的是 priority、depends_on、asyncio 并行和结果聚合；同时 Strategy Matrix 里的 scenario→schedule 也是确定性规则。也就是说，LLM 决策和确定性编排实际上已经分离，只是代码抽象层没有显性表达出来。

所以后续我们没有推倒重写，而是做了一次架构收敛：IntentionAgent 只负责场景识别和实体提取，Strategy Matrix 作为确定性 Policy，OrchestrationAgent 收敛成普通 Scheduler，负责调度和执行。核心原则就是“LLM 负责不确定性的理解和推理，确定性的策略和执行交给代码”。

改造后 107 个测试全部通过，离线评测没有下降，所以这次不是为了改变业务行为，而是重新归属已有能力，降低不必要的 Agent 抽象。对我来说最大的收获是，Agent 系统不应该为了 Multi-Agent 而 Multi-Agent，真正重要的是明确 LLM 决策边界，并通过 Evaluation 验证架构调整有没有带来实际收益。



> 场景：一个多 Agent 的工单智能诊断系统（Intention → Orchestration → Code/Operation/Data/Resolution），上线前离线评测端到端 Pass@1 只有 77.27%，10 个失败。

**一句话复盘**：这个项目我学到的是比较看重的是评测驱动的优化过程。上线前离线评测端到端 Pass@1（第一次尝试就给出正确答案"的比例） 只有 77.27%，10 个失败。一开始我下意识以为是 RAG 或记忆系统的问题，确实从 RAG 侧做过一些优化，包括query/recall、重排、父文档召回、缓存等，但后来发现这些优化没有解决主要失败样本，后续给评测脚本加了「分环节命中率统计」把整个链路切成6段（意图识别→实体抽取→RAG检索→工具调用→Agent决策→最终校验）（Intent / Entity / RAG / Tool / Agent / Verification） ，用数据定位到真正的瓶颈是 **Entity Resolution（实体解析）**——多数失败不是缺 ticket_id，而是「商户名 → merchant、id」这层解析缺失（原正则 `\b\d{4,6}\b` 在 Python Unicode 模式下把中文当单词字符，导致「商户2037」里的数字匹配不到），以及「只有商户号时无法反查订单号」；于是我按「数据闭环」做了三阶段优化：① Entity Resolution（商户名→ID、商户→订单反查）、② Tool 能力（新增 `resolve_merchant（商户名转ID）` / `resolve_order商户ID反查订单号）`mantic 软匹配），每一步都重新跑评测量化验证，Pass@1 依次走到 81.82% → 86.36% → 90.91% → 100%。这件事最大的收获是：**「用数据定位瓶颈、用评测闭环验证」远比「凭直觉预判优化」高效**——之前做的 RAG 增强和缓存其实都没打在这个真正的瓶颈上。
优化 3 是**评测方法升级**（不是改诊断逻辑），它诚实的原因是——那 4 个失败根因其实都判断对了，只是「回调超时」被写成「回调…超时」、「规则不一致」写在 `summary` 而不是 `root_cause`，属于评测的假阴性。所以这 4 个「+9.09pp」是修复评测缺陷，不是放水。建议你在面试时主动点破这层，会显得更专业。
